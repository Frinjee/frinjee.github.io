## Website assets (required references)

### file_list.txt

* **Reference** * file_list.txt synced from dropbox to retrieve asset content names and their proper location

Before adding or rewriting asset paths:

1. Locate `file_list.txt` at the repo root or the Dropbox sync path the user indicates.
2. Use the listed names and locations exactly — do not invent filenames or relocate assets without updating that list.
3. If the file is missing, ask where the Dropbox sync lives; do not guess asset paths.

### mp-skin-refs

* **Reference** * mp-skin-refs folder synced from dropbox for ensuring development output matches correct skin reference.

Before changing media-player / skin UI:

1. Open the matching reference in `mp-skin-refs`.
2. Match layout, spacing, control order, and visual states to the reference.
3. If the folder is missing, ask for the sync path; do not invent a skin.

Many layout images are referenced in HTML/CSS but not all are committed — treat Dropbox-synced assets as source of truth via the two references above.

## When generating web code

Generate web development code (HTML, CSS, and JavaScript) that is optimized for both general web use and mobile-first experiences. Ensure all generated code adheres to the specified best practices and standards.

Full HTML / CSS / JS rules: [web-standards.md](web-standards.md)

### Project application notes

- **Mobile 1:1**: Include viewport meta, relative units, mobile-first media queries. Do not ship desktop-only fixed shells (legacy `#page { width: 900px }` is historical — new work must be responsive via Unsemantic).
- **CSS grid framework**: Use [Unsemantic](https://unsemantic.com/about) for mobile layout (`grid-container`, `grid-100`, `tablet-grid-*`, `mobile-grid-*`, etc.).
- **CSS methodology**: Prefer Maintainable CSS / BEM-style naming consistent with existing classes (`music_player_*`, `activity-*`, `top-*`). Keep section comment blocks in CSS when extending `main.css`.
- **JS**: Prefer clear, clean-code patterns. Existing pages often use jQuery — match the page's existing stack unless asked to modernize. Keep touch/mobile interaction parity with desktop.
- **Accessibility & performance**: Semantic HTML, meaningful `alt`/`aria-label`, avoid layout thrash and unnecessary assets.
- **Unconventional tricks**: Only when logically sound and justified in a short comment.

### Web output format

The output should consist of the generated HTML, CSS, and JavaScript code. Clearly delineate each section.

Use fenced code blocks labeled HTML, CSS, and JavaScript.
